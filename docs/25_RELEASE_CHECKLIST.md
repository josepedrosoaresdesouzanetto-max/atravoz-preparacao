# Checklist de entrega futura — não autoriza publicação

- [x] Esqueleto testado antes do único push privado.
- [x] URL, privacidade e commit inicial registrados.
- [x] Desenvolvimento posterior mantido local.
- [x] Origem assistida por IA e preparação anterior ao evento documentadas.
- [x] Registro, fila, API, recibos, anexos e central testados no ambiente disponível.
- [x] Regras/contratos de IA, contingência e avaliação sintética executados.
- [x] Limitações de Bluetooth/hardware/modelo real explícitas.
- [ ] Revisão humana do código, segurança e corpus.
- [ ] Ficha oficial recebida e proposta ajustada/aprovada conforme organização.
- [ ] Autorização/elegibilidade de reutilização do código anterior ao evento.
- [ ] Equipe/papéis acordados; validador identificado e teste realizado.
- [ ] Celulares reais e cenários de permissão/rede/armazenamento testados.
- [ ] Modelo real escolhido, disponível e avaliado; uso de dados aprovado.
- [ ] Licença e marca definitivas.
- [ ] Implantação HTTPS, contas, retenção e backup aprovados.
- [ ] Nova autorização explícita para enviar versão final.
- [ ] Código aprovado no repositório oficial e CI final realmente executada.
- [ ] Deploy público demonstrativo autorizado e verificado em celular.
- [ ] Pitch ensaiado em três minutos, gravação baseada em execução real.

Não marcar itens futuros pela simples existência de código ou arquivo. Falhas/bloqueios devem acompanhar a entrega. Este checklist não configura release, push ou deploy automático.
